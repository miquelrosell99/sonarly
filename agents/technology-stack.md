## Technology Stack

- **Runtime:** Node.js 20
- **Package manager:** pnpm 9 (workspace monorepo)
- **Language:** TypeScript 5.9
- **Backend:** Fastify 5, `better-sqlite3`, `zod`, `music-metadata`, `chokidar`, `bcrypt`
- **Frontend:** React 18, Vite 6, Tailwind CSS 3, wouter, Zustand, @tanstack/react-query 5, @tanstack/react-virtual 3, @dnd-kit (core/sortable)
- **Deployment:** Docker + Docker Compose, single container serves both API and built web UI
- **Testing:** Vitest 3

### Frontend contract module (`packages/web/src/contract/`)

Typed client for the v2 API contract, generated from `.worktrees/go-rewrite/v2/api/openapi.yaml`:

- `schema.ts` — types generated by `openapi-typescript` (devDependency). Regenerate with `pnpm contract:gen` (script: `packages/web/scripts/contract-gen.mjs`); the file is committed and must not be hand-edited.
- `wrapper.ts` — thin typed `request()` over the generated `paths` table (path/query/body inference, `{error}` envelope → `ApiError`, same-origin relative paths, 401 → `sonarly:unauthorized`) plus per-domain call-site helpers (`songs`, `albums`, `artists`, `genres`, `playlists`, `players`, `search`). Deliberately not a framework.
- `capabilities.ts` — v1/v2 capability shim: probes `GET /api/songs?limit=1` once at boot (cached forever via react-query) and exposes `{ server, rawUpload, hasFilePath, syncedLyricsArray }`; total/heuristic, falls back to v1 defaults. The client keeps working against v1 and v2 without a flag day.

`lib/api.ts` remains the live v1 gateway; call sites migrate to `contract/` one domain at a time.

### Code splitting & bundle budget (FF2)

The production build is code-split (audit FF2 fix, 2026-09-26):

- Every route in `App.tsx` is a `React.lazy` component via the `lazyRoute()` helper, with a route-shaped skeleton from `components/Skeletons.tsx` as its Suspense fallback. `Login`/`Setup` stay static (first paint for unauthenticated visitors); shared chrome (Layout, TopBar, Sidebar, PlayerBar, AudioController, NowPlaying overlay) stays in the entry chunk.
- `vite.config.ts` `manualChunks` splits vendors by independent release cadence: `react` (react/react-dom/scheduler), `tanstack` (react-query + react-virtual), `dnd-kit`, `wouter`, `zustand`.
- `scripts/bundle-budget.mjs` runs as the final `pnpm build` step and rejects the build when: entry chunk > 250 KiB raw, any single lazy chunk > 350 KiB raw, or total JS > 900 KiB raw. It prints a full chunk table plus the offenders.

### List virtualization

`components/ui/VirtualGrid.tsx` + `VirtualList.tsx` (built on @tanstack/react-virtual, overscan 5) window long lists against the app's scroll container (`<main>`, resolved at runtime by `useScrollParent.ts` — never hardcoded). `LibraryView` virtualizes lists longer than 150 rows/cards (`virtualizeThreshold` prop); dnd-sortable lists (queue editor) and grouped lists keep the unwindowed renderer. With no scroll container resolvable (jsdom), everything renders fully.

## Technology Stack

- **Server:** Go 1.23, `net/http` + chi v5, `modernc.org/sqlite` (pure Go, no CGO; WAL, foreign keys, busy_timeout, single writer connection)
- **Server layout:** modular monolith — one package per domain under `server/internal/modules/<name>/` (catalog, library, ingest, playlists, opensubsonic, …)
- **Migrations:** embedded numbered SQL files, ledger-tracked (`schema_migrations`), per-file transactions
- **Runtime tooling:** ffmpeg (transcoding), python3 + mutagen (tag writing) — both in the Docker image
- **Web client:** React 18, Vite 6, Tailwind CSS 3, wouter, Zustand (client state), @tanstack/react-query 5 + @tanstack/react-virtual 3 (server state + virtualization), @dnd-kit (core/sortable)
- **Web package manager:** pnpm 9 (workspace: `web` only)
- **Deployment:** Docker + Docker Compose, single all-in-one image (`docker/Dockerfile`) serves the web client, `/api`, and `/rest`
- **Testing:** Go `testing` (server), Vitest 3 (web)

### API contract (`server/api/openapi.yaml` + `web/src/contract/`)

- `server/api/openapi.yaml` — OpenAPI 3.1 contract for the native `/api` surface, hand-maintained next to the Go DTOs. A chi.Walk coverage test fails the build if a route and the spec drift apart in either direction. Lint with `npx @redocly/cli lint openapi.yaml` (config: `server/api/redocly.yaml`).
- `web/src/contract/schema.ts` — types generated by `openapi-typescript`. Regenerate with `pnpm --filter @sonarly/web contract:gen` (script: `web/scripts/contract-gen.mjs`); the file is committed and must not be hand-edited.
- `web/src/contract/wrapper.ts` — thin typed `request()` over the generated `paths` table (path/query/body inference, `{error}` envelope → `ApiError`, same-origin relative paths, 401 → `sonarly:unauthorized`) plus per-domain call-site helpers.
- `web/src/contract/capabilities.ts` — server detection left over from the server-rewrite cutover (probes `GET /api/songs?limit=1` once at boot). Production runs the Go server; the shim still detects it correctly. Scheduled for removal as follow-up cleanup.
- Domain entity types (shared with the UI but server-authoritative by convention) live in `web/src/types/` — migrated from the retired `@sonarly/shared` package.

### Code splitting & bundle budget

The production build is code-split (audit FF2 fix, 2026-09-26):

- Every route in `App.tsx` is a `React.lazy` component via the `lazyRoute()` helper, with a route-shaped skeleton from `components/Skeletons.tsx` as its Suspense fallback. `Login`/`Setup` stay static (first paint for unauthenticated visitors); shared chrome (Layout, TopBar, Sidebar, PlayerBar, AudioController, NowPlaying overlay) stays in the entry chunk.
- `vite.config.ts` `manualChunks` splits vendors by independent release cadence: `react` (react/react-dom/scheduler), `tanstack` (react-query + react-virtual), `dnd-kit`, `wouter`, `zustand`.
- `scripts/bundle-budget.mjs` runs as the final `pnpm build` step and rejects the build when: entry chunk > 250 KiB raw, any single lazy chunk > 350 KiB raw, or total JS > 900 KiB raw. It prints a full chunk table plus the offenders.

### List virtualization

`components/ui/VirtualGrid.tsx` + `VirtualList.tsx` (built on @tanstack/react-virtual, overscan 5) window long lists against the app's scroll container (`<main>`, resolved at runtime by `useScrollParent.ts` — never hardcoded). `LibraryView` virtualizes lists longer than 150 rows/cards (`virtualizeThreshold` prop); dnd-sortable lists (queue editor) and grouped lists keep the unwindowed renderer. With no scroll container resolvable (jsdom), everything renders fully.
